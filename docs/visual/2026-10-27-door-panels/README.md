# Sliding doors: the surround must stay still

The reported defect was real: the door image includes masonry at its edges,
and the renderer translated that complete image as the slab slid open. The
stone border therefore travelled through the doorway with the door.

`Assets.doorLeaf` now caches just the inner 48×60 leaf (x8,y4) in a 64×64 texture.
The renderer uses it for closed and moving doors and cell gates, before crack
and fire effects. The actual world walls and recessed jambs provide stationary
masonry. There is no separate masonry strip attached to the moving face.
Using the same fit in both states avoids a switch when opening begins.

The original source/export paintings and coloured lock patches are unchanged.
The cache keys by source identity, so independently decoded or failed images
retain their own painting/fallback leaf. No per-frame crop allocation, new asset
URL, eager region warmup or source repaint is introduced in play.
Door intersections, texture scroll fractions, collision, opening timing,
targeting and seeded rules are unchanged. This is a door-surface fix; game
balance simulations are unnecessary.

## Visual verification

- 60 before captures show three regions, ordinary/cell doors, five opening
 fractions and both phone widths, on the previous v0.9.45 renderer.
- 260 after captures cover all 13 regions with the same two door kinds, five
 fractions and 320/390px widths. These use controlled frozen geometry/animation
 fractions through the shipped loader/renderer, not native opening commands.
- `native.cjs` separately runs the real use command and running animation at
 320×667,390×844 and740×360:36 sampled canvas frames plus six closed/open UI
 screenshots. Each verifies moving columns appear and disappear, and the door
 becomes OPEN. Doorway geometry and enemy removal are supplied fixtures.
- Four installed upgrade/retry profiles from v0.9.43 to v0.9.46/build61/cache121
 preserve the saved hero fields and decode current paintings offline. Their
 images/evidence are in `upgrade/`; historical upgrade evidence remains intact.

`capture.cjs` reproduces the **after** set; its default is the current renderer.
The before set is historical evidence, not generated by the fixed renderer.
`native.cjs` reproduces real animations. The installed-art audit tool now reads
current version/build/cache metadata and accepts `AUDIT_OUTPUT_DIR`, preserving
older records when testing a newer build. No physical-device checks were run.

## Validation

eight native-opening/region/late-cache cases and the native recessed-jamb check.
The new renderer matrix checks 104 region/cell/opening routes per project
(208 total), no full-surround texture draws, fully open clearance, and unchanged
run/dice. A synthetic marked-surround image checks the surround is excluded,
the lock remains, source pixels stay unchanged and a new source gets a new leaf.

fixture and failed its state-neutrality assertion once. It now clears live
creatures, takes the initial render state once, awaits the exact requested door
and gate images, then compares state/dice around rendering only. All 208 final
routes pass. The first capture assertion also incorrectly expected moving
columns at fully-open zero; zero columns is now explicitly checked.

`npm test` passed all 751 rules plus type, release, art, security, narration and
offline checks. The first isolated 4×CPU performance sample missed painted 29.3fps
against 30fps; unchanged main passed 30.7fps; the paired fix sample passed every
budget (42.1/38.5/38.4/32.5/47fps; startup2027ms). All three measurements are
retained in [validation.json](validation.json); no thresholds changed.
