# Security review — 20 October 2026

Reviewed baseline: `996b65c22853d8f71eaee929542ff750e04d49e6` (v0.9.11,
build 26), including the new Pack tools and Journal guides. Release target for
the fixes: v0.9.12, build 27.

## Scope

Reviewed save decoding and loading, item transfers, recent HTML rendering,
device-local preferences, replay messaging/storage, telemetry and public
statistics, Redis requests, service-worker boundaries, deployment headers and
exclusions, dependencies and CI permissions. Tests use synthetic data and a
mocked telemetry store. No hostile requests were sent to production and no
account settings or production credentials were inspected.

## Confirmed findings and fixes

**Medium: imported floor loot could inject HTML into a consumable belt count.**
The save validator checked item types and finite quantities in the hero's
inventory and equipment, but omitted floor loot and NPC stock. A crafted floor
item with a string quantity passed import, became carried through ordinary
pickup, and reached an unescaped belt count. The same missing validation applied
to trader stock. A player must import a crafted save and carry/pin the affected
item. This is DOM injection; the existing CSP restricts script execution, and
arbitrary script execution was not demonstrated.

A headless reproduction against the baseline confirmed both successful import
of the malformed floor item and its raw tag appearing in the generated belt
HTML. The fix applies the existing item validator to every floor-item list and
NPC stock list before replacing either the saved or live hero. It also rejects
malformed container shapes and bounds those lists. Belt quantities are escaped
in both visible text and accessible-label attributes as a second safeguard.
Valid item values and game rules are unchanged. The offline cache is incremented
so an installed game can fetch the corrected modules when this change ships.

**Low: legacy Hall migration could modify Object.prototype and fail to load.**
The class lookup accepted inherited table keys, including `__proto__`, from
device-local Hall data. With no separate progress record, migration wrote the
win count into `Object.prototype.normal`, then threw while cleaning progress.
An isolated baseline reproduction confirmed both effects. This requires altered
or corrupt browser storage; a normal save-code import already rejects that
player class. No cross-user or server-side access was demonstrated.

Migration and progress writes now require own table IDs, and Hall display
filters malformed entries. Progress, Wick and fallen-hero counters accept only
finite numeric primitives or legacy numeric strings, so stored objects cannot
throw through conversion methods. Progress discovery lists also reject
inherited relic and combination IDs. Valid Hall entries and progression remain
unchanged.

## Verification

- `npm run test:security`: passed. Added forged floor/stock quantities and IDs,
  malformed item lists and malformed NPC entries to the import-preservation
  checks. Existing gzip expansion, prototype/nesting, maximum-size legitimate
  dungeon, file-boundary, telemetry and store-error regressions still pass.
  Added legacy Hall prototype checks, valid-Hall preservation and damaged
  progress-counter/discovery tests as well.
- `npm audit --json`: zero known advisories in the locked dependency tree at
  review time (27 dependency entries; no runtime packages).
- Limited scan of 363 tracked UTF-8 files below 2 MB: no matches for the tested
  private-key, GitHub-token, AWS-access-key and OpenAI-style key patterns. No
  tracked environment/private-key files were found. This scan covers the current
  tree, not Git history or all possible credential formats.

- Final `npm test`: passed, including all 732 rule checks. The Hall retention
  regression confirms that older lists longer than fifty are sorted by score
  before trimming; filtering invalid entries does not discard higher scores.
- Focused Chromium run: 58 checks passed across phone and small projects for
  security, replay, gear tools and Journal guides. A further 33 checks passed
  for security and progression, including the new Hall migration regression
  on both phone sizes. Forged imports preserve the live and saved hero; belt
  counts remain text in both visible content and accessible attributes.
- `npm run check:agents` and `git diff --check`: passed. Publication additionally
  runs both full Chromium projects, the isolated frame-rate budget and the
  exact-commit pre-push suite. CI gates the version release on all seven required
  jobs, including WebKit and its separate performance runner.

## Remaining limits

The [previous review](SECURITY-2026-10-16.md) and [security policy](../SECURITY.md)
describe unchanged boundaries: public telemetry is unauthenticated, local
scores are player-controlled, and save codes are not encrypted. Account MFA,
hosted quotas, trusted proxy configuration and production store permissions
were not verified here. No balance simulation is needed for this change: valid
gameplay, RNG, costs and controls are unchanged. This source review and its
tests do not establish that every possible vulnerability has been found.
