# Security review — 16 October 2026

Reviewed baseline: `0b49d11c2deb611c737fef762707132db0d10c90` (release 1.0.0,
build 3). Fixes publish as build 4. This review changes input validation,
presentation and server/development boundaries, not valid gameplay rules.

## Scope

Source review covered the telemetry/statistics functions and Redis client,
browser HTML sinks and URL assignment, save-code decoding/loading, local
storage, replay messages and isolation, service-worker caching, static serving,
deployment headers/exclusions, dependencies and CI permissions/runtime.
The production site received read-only header/readiness requests; no hostile payloads
were sent to production and no real reports or store credentials were accessed.

The app has no accounts, authentication tokens in the browser, payments,
database query strings or user-supplied server-side execution. Redis commands
are JSON arrays, not interpolated Redis command strings. Replay messages already
check origin and source; imported saves cannot supply a trusted replay context.
Browser code uses fixed module imports and does not evaluate saved scripts.
Imported recordings are removed before persistence as well as from live state,
so a reload cannot revive an untrusted starting context.

## Findings and fixes

| Finding | Severity and preconditions | Resolution |
| --- | --- | --- |
| Imported values reached HTML without complete escaping | Medium: a player imports a crafted save; quote injection was also possible through a chosen hero name. The existing CSP reduced script execution opportunities but did not prevent DOM injection. | Escape attribute quotes, saved numeric-looking values, result fields, log classes and journal locations; validate core save field types before loading. Browser regressions assert no injected elements or attributes. |
| Unbounded save-code expansion and invalid dungeon allocations | Medium: a player imports a crafted code/file. A 21,776-character code expanded to 16,777,216 bytes in the baseline, with no upper bound. | Limit encoded input/file reads to 24 MiB and decoded output to 16 MiB; count gzip output while reading and cancel when exceeded. Validate floor dimensions, tiles, ids, finite core numbers, depth, nesting and prototype keys before state assignment. |
| Malformed telemetry fields could throw outside validation handling | Low: unauthenticated malformed JSON fields such as numeric objects with shadowed conversion methods. | Avoid implicit object coercion; bound numeric/text fields; measure UTF-8 bytes for parsed and streamed bodies, discard further chunks after rejection and handle aborted uploads. |
| Public crash counters contained parts of error messages | Medium privacy risk: an opt-in error includes sensitive input; stripping HTML does not remove personal information. | New counters use digests. Public stats transforms legacy counters to opaque signatures too. Raw reports/error details remain in the private store; consent text states that error details can contain input. |
| Save exports carried unnecessary local replay memories | Medium privacy risk: sharing a hero also included the recording's starting local-storage snapshot, including unrelated Hall history. | Export only the current game state without its local recording. Keep the browser's recording intact; discard recording data from imported codes before persistence and verify it stays unavailable after reload. |
| Cross-site beacons, concurrent crash-counter growth and cache retention | Low: public telemetry could accept another site's beacon, the crash-kind cap was non-atomic, and the service worker cached statistics despite the server's policy. | Reject cross-origin browser reports, make the distinct-crash cap/increment one atomic Redis script, digest rate-limit addresses, use minute windows, and bypass API/cross-origin service-worker requests. Bound Redis waits and reject command errors. |
| Development server path escape and malformed URI crash | Low: access to the loopback development server. The prefix check admitted a sibling directory sharing the repository name; symlinks also escaped the root. Not the Vercel production server. | Check path-component and resolved-file boundaries, deny hidden paths and node_modules, catch malformed encodings, and limit methods. Preserve byte-range media and HEAD support. |
| CI runtime and token exposure | Low hardening: workflow jobs used Node 20, past upstream support, and default checkout credential persistence. | Use Node 24 in CI and the package runtime requirement, explicit read-only repository permissions and non-persisted checkout credentials. Exclude development files from deployment. |

The Redis client also requires HTTPS and refuses redirects before following a
destination with report data. Its credentials remain server-only.
Save strings and log lines are bounded, and dice-log formatting uses linear
searches so repeated incomplete roll prefixes cannot cause regex backtracking.
Imported progression is also bounded so finite but enormous experience cannot
trigger billions of rank catch-up iterations on the next kill.

Build and service-worker cache identifiers are incremented so installed copies
fetch the fixed code. Camera, microphone and geolocation are disabled through
Permissions-Policy. The existing CSP, frame restriction, nosniff, referrer policy
and HTTPS policy remain in place.

## Evidence

- `npm audit --json`: zero known advisories in the locked dependency tree at
  review time (27 dependency entries, development tooling; no runtime packages).
- Credential-pattern scan of 375 UTF-8 text blobs below 2 MB across all 19 reachable commits:
  no candidates for supported GitHub token, AWS access-key, private-key, Stripe,
  OpenAI/Anthropic-style key or JWT patterns. No tracked credential/env files were found. This is a
  limited pattern scan, not proof that no possible secret exists.
- Live root headers returned the configured CSP, `X-Content-Type-Options`,
  `X-Frame-Options`, `Referrer-Policy` and HSTS. Account settings were not inspected.
- The public statistics endpoint returned HTTP 200 with `ready: false`, so the
  telemetry store was not configured at review time. No report contents were used.
- `test/security.js`: compressed/plain oversize rejection, prototype/nesting
  rejection, malformed shapes, live/save preservation, a valid 16-floor Large
  dungeon round-trip, and real loopback traversal/symlink/malformed-URI probes.
- `test/api.js`: malformed fields, byte limits, origin rejection, rate keys,
  private crash signatures including legacy data, command errors and store-off
  behavior. Store tests use a mock; no live Upstash integration was exercised.
- `test/browser/security.spec.js`: quoted names, hostile imports, journal/end
  screen markup and service-worker API-cache bypass in real Chromium.
- Final focused Chromium coverage: 23 security/replay/reporting cases passed
  across the phone and small projects, including gzip-bomb rejection and export
  privacy. The existing combat-roll display/toggle regression also passed.
- Isolated frame-rate budget at 4× CPU throttle: 42.5–54.8 fps across its four
  scenes, above the 30 fps requirement. Full headless checks run again on the
  exact pushed commit through the pre-push hook; CI also checks WebKit.

## Remaining limits

The telemetry API remains intentionally public and unauthenticated. Reports can
be forged by direct clients or distributed senders; origin checks are a browser
abuse control. Upstash/Vercel quotas, WAF rules, account permissions, MFA, billing
limits, access logs and credential rotation were not verifiable from this
workspace. Address throttling relies on Vercel's trusted forwarding headers.

Save checking covers structural/resource boundaries, not every historical or
semantic game state. Corrupt unsupported fields can still produce a refused or
unplayable run; the checks do not certify arbitrary edited saves or honest scores.
Only run trusted same-build recordings. Browser storage can be erased or read by
code with access to the origin, and sharing a save shares its included data.

No balance retuning is included: valid simulation rules and bot decisions are
unchanged. The existing balance audit remains applicable. Passing source and
regression checks is not a guarantee against every vulnerability or a substitute
for an independent penetration test.
